## Безопасность

- **helmet**: подключает заголовки безопасности и скрывает заголовок `X-Powered-By`[cite: 1].
- **CORS**: доступ ограничен только доверенным доменам из `CORS_ORIGINS` (например, `https://agromarket-ЛОГИН.vercel.app`, `http://localhost:5173`)[cite: 1].
- **Rate limit**: ограничение на `/api/auth/login` и `/api/auth/register` — не более 10 попыток за 15 минут[cite: 1].
- **Валидация zod**: проверка входящих данных для маршрутов регистрации (`registerSchema`), входа (`loginSchema`), создания и обновления товаров (`productSchema`, `productUpdateSchema`), а также валидация ID параметров URL (`idParam`)[cite: 1].

### Ответы на вопросы

- **npm audit: что нашли, что исправили, что оставили и почему**: проверены продакшен-зависимости с помощью `npm audit --omit=dev`[cite: 1]. Выявленные уязвимости обновлены до безопасных версий[cite: 1]. Уязвимости в `devDependencies` оставлены, так как они не попадают на продакшен[cite: 1].
- **Были ли секреты в истории git**: выполнена проверка истории с помощью `git log --all -p` и `git ls-files`[cite: 1]. Действующие секретные ключи Neon и `JWT_SECRET` в истории репозитория не найдены[cite: 1].
- **Был ли возможен mass assignment (role: admin) до валидации**: да, до подключения Zod передача `req.body` напрямую могла позволить зарегистрировать пользователя с ролью `admin`[cite: 1]. Схема Zod отбрасывает незаявленные поля, предотвращая изменение роли[cite: 1].
- **Зачем trust proxy на Render**: Render работает за прокси-сервером/балансировщиком[cite: 1]. Без настройки `app.set('trust proxy', 1)` Express видит IP прокси-сервера, из-за чего rate limit блокирует сразу всех пользователей[cite: 1].
- **Почему проверки в React-форме недостаточно**: клиентскую валидацию легко обойти отправкой запроса напрямую через Postman, cURL или консоль браузера[cite: 1]. Валидация на клиенте создана для UX, а на сервере — для реальной защиты данных[cite: 1].
- **Время отката на Vercel**: Instant Rollback на Vercel занимает ~5–10 секунд[cite: 1]. `git revert` необходим для сохранения корректной истории в репозитории `git` и предотвращения повторного деплоя сломанной версии при следующем push в `main`[cite: 1].
- **Использовал(а) ли ИИ и для чего**: ИИ использовался для составления схем Zod, генерации тестов Supertest и оформления ответов на лабораторную работу[cite: 1].
